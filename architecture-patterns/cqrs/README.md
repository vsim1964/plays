# CQRS — разделение команд и запросов

**Основной вопрос:** зачем отделять операции изменения данных от операций их чтения?

**CQRS** означает *Command Query Responsibility Segregation*. Команда (**Command**) изменяет состояние; запрос (**Query**) получает данные, ничего не меняя. В данном примере для этих обязанностей выделены две самостоятельные модели.

## Распределение файлов

- `write-model.js` — `WriteModel`: метод `execute({type:"ChangeRank", index, rank})` применяет команду, `snapshot()` возвращает копию состояния.
- `read-model.js` — `ReadModel`: `project(snapshot)` строит проекцию для чтения, `queryRoster()` возвращает её.
- `view.js` — отображает результаты запроса и передаёт действие пользователя.
- `main.js` — передаёт команду в WriteModel, синхронно обновляет ReadModel и выводит результат.

## Маршрут изменения звания

```text
View → Command: ChangeRank
                ↓
WriteModel.execute(command)
                ↓
Снимок изменённого состояния
                ↓
ReadModel.project(snapshot)
                ↓
Query: read.queryRoster()
                ↓
View.render(...)
```

При обычном чтении таблицы вызывается `read.queryRoster()`. Изменение звания не проводится через этот метод: оно проходит исключительно через `write.execute()`.

## Небольшой эксперимент

В `main.js` временно удалите строку `read.project(snapshot)` из обработчика кнопки. WriteModel изменится, но View продолжит читать старую проекцию из ReadModel. Это наглядно показывает, что в CQRS модели чтения и записи могут на некоторое время расходиться.

## Чем отличается

В **Layered Architecture** чтение и запись обычно проходят через общий сервис и репозиторий. CQRS разделяет эти обязанности, вплоть до отдельных моделей и хранилищ. В нашей демонстрации оба состояния находятся в памяти и синхронизируются сразу; асинхронная доставка и отдельные базы данных здесь не используются.

## Как запустить

Откройте корень репозитория в VS Code и запустите **Live Server**. Перейдите к странице `architecture-patterns/cqrs/index.html`. Используется `<script type="module" src="main.js">`, поэтому прямое открытие через `file://` не рекомендуется.

В интерфейсе выберите бойца, задайте другое звание и нажмите **«Изменить звание»**. Сравните изменённую строку таблицы с журналом «Трассировка: кто вызвал кого?». При обновлении страницы данные возвращаются к исходным: в примере они изменяются только в памяти браузера, без записи на диск.

`index.html` задаёт элементы интерфейса, `style.css` отвечает за оформление, `data.js` содержит одинаковые для всех девяти примеров сведения об 11 вымышленных бойцах. Это общая учебная основа; архитектурные различия находятся в остальных файлах.
