# Архитектурные паттерны — девять работающих примеров

Все примеры используют один и тот же набор из 11 вымышленных бойцов, одинаковую HTML-таблицу и действие «Изменить звание». Меняется только архитектура — расположение ответственности, способ передачи данных и порядок вызовов.

## Запуск

Запустите корень репозитория через **Live Server** в VS Code и откройте `architecture-patterns/index.html`. Все примеры используют стандартные ES-модули (`type="module"`): открывать файлы через `file://` не следует.

Изменения выполняются **в памяти браузера**, исходный JSON и исходные учебные файлы в корне репозитория не изменяются. Обновите страницу, чтобы вернуть начальные сведения.

## Порядок изучения

| Папка | Что сравнить |
|---|---|
| [MVC](./mvc/index.html) | Контроллер принимает действие, модель меняется, View отображает состояние. |
| [MVP](./mvp/index.html) | Presenter получает действия пользователя и командует пассивным View. |
| [MVVM](./mvvm/index.html) | ViewModel хранит реактивное состояние, View подписывается на него. |
| [Flux](./flux/index.html) | Action → reducer → store → view: данные идут в одном направлении. |
| [Component-Based](./components/index.html) | Страница собирается из самостоятельных компонентов с входными данными. |
| [Layered](./layered/index.html) | Контроллер → сервис → репозиторий; каждый слой решает свою задачу. |
| [Clean / Hexagonal](./clean/index.html) | Бизнес-правила отделены от DOM и хранилища посредством портов. |
| [Event-Driven](./events/index.html) | Модули обмениваются событиями, не вызывая друг друга напрямую. |
| [CQRS](./cqrs/index.html) | Команды меняют состояние, запросы читают отдельную проекцию. |

В каждом каталоге: `index.html`, `style.css`, `data.js`, `main.js` и отдельные модули с архитектурными ролями. Лог выполнения показывается прямо на странице.

**Педагогические упрощения.** Примеры не претендуют на исчерпывающие реализации фреймворков. В MVVM реактивность создана вручную с `subscribe`; в CQRS проекция обновляется синхронно; в Clean Architecture используется репозиторий в памяти; в Events события доставляются синхронно. Эти детали оставлены простыми, чтобы показать принцип разделения ответственности.

`data.js` повторяется в каждой папке намеренно: каждый пример независим и его можно изучать отдельно.
