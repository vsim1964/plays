# MVC — Model, View, Controller

**Основной вопрос:** кто принимает действие пользователя, кто хранит данные и кто их показывает?

MVC делит обязанности между **моделью (Model)**, **представлением (View)** и **контроллером (Controller)**. Наш пример — облегчённый, браузерный вариант MVC: контроллер координирует работу, не используя серверный шаблонизатор.

## Распределение файлов

- `model.js` — класс `SquadModel`: создаёт собственную копию массива, возвращает бойцов через `all()` и изменяет звание посредством `changeRank()`. Модель не обращается к HTML.
- `view.js` — `createView()`: находит DOM-элементы, отображает строки в `render()`, принимает события интерфейса через `onSave()` и `onPick()`.
- `controller.js` — `SquadController`: связывает действия View с вызовами Model, затем инициирует обновление View.
- `main.js` — собирает три части в приложение: `new SquadController(new SquadModel(), createView())`.

## Маршрут изменения звания

```text
Нажатие кнопки во View
        ↓
SquadController → model.changeRank(index, rank)
        ↓
SquadModel меняет объект бойца
        ↓
controller.refresh()
        ↓
view.render(model.all()) → HTML-таблица
```

Посмотрите на обработчик `view.onSave(...)` в `controller.js`. Контроллер сначала изменяет модель, потом вызывает `refresh()`. Без последнего шага таблица сохранит прежние данные, хотя массив уже изменён.

## Небольшой эксперимент

Временно закомментируйте `this.refresh()` внутри обработчика сохранения. Изменение модели произойдёт, но таблица не обновится. Верните вызов — интерфейс снова станет согласован с данными.

## Чем отличается

От **MVP** эта версия отличается тем, что мы называем посредника контроллером и используем его для координации действий. В маленьком примере MVC и MVP внешне очень похожи; строгая граница между ними зависит от конкретного варианта паттерна. От **MVVM** отличается отсутствием подписки View на состояние: обновление явно запускает контроллер.

## Как запустить

Откройте корень репозитория в VS Code и запустите **Live Server**. Перейдите к странице `architecture-patterns/mvc/index.html`. Используется `<script type="module" src="main.js">`, поэтому прямое открытие через `file://` не рекомендуется.

В интерфейсе выберите бойца, задайте другое звание и нажмите **«Изменить звание»**. Сравните изменённую строку таблицы с журналом «Трассировка: кто вызвал кого?». При обновлении страницы данные возвращаются к исходным: в примере они изменяются только в памяти браузера, без записи на диск.

`index.html` задаёт элементы интерфейса, `style.css` отвечает за оформление, `data.js` содержит одинаковые для всех девяти примеров сведения об 11 вымышленных бойцах. Это общая учебная основа; архитектурные различия находятся в остальных файлах.
