# Clean / Hexagonal Architecture — внутренние правила и внешние адаптеры

**Основной вопрос:** как сохранить бизнес-логику независимой от HTML, браузера и способа хранения данных?

Центральное правило живёт в `domain.js`, операция приложения — в `usecase.js`, а внешний механизм хранения подключается как адаптер. Пример объединяет близкие идеи Clean Architecture и Ports & Adapters (Hexagonal); это учебное упрощение, не полный эталон обеих архитектур.

## Распределение файлов

- `domain.js` — `promote(fighter,newRank)`: проверяет звание и возвращает новый объект. Ни одного DOM-вызова.
- `usecase.js` — `createChangeRankUseCase(repository)`: осуществляет сценарий изменения звания через переданный интерфейс репозитория (**порт**).
- `adapter.js` — `MemorySquadAdapter`: реализует ожидаемые методы `getAll()` и `save()`, используя массив в памяти.
- `view.js` — отображение и события DOM.
- `main.js` — **composition root**: создаёт адаптер, передаёт его в сценарий и подключает View.

## Маршрут изменения звания

```text
View.onSave
      ↓
Use case: changeRank(index, rank)
      ↓
Repository port: getAll()
      ↓
Domain: promote(fighter, rank) → новый объект
      ↓
Repository port: save(index, updated)
      ↓
main.render() → View
```

**Порт** здесь не объявлен специальным `interface` (в обычном JavaScript такого ключевого слова нет): это ожидаемый контракт из двух методов. Сценарий зависит от этого контракта, а не от конкретного способа хранения.

## Небольшой эксперимент

Вместо `MemorySquadAdapter` можно создать другой адаптер с теми же `getAll()` и `save()`. `domain.js` и `usecase.js` менять не потребуется. Для настоящего серверного API пришлось бы ещё согласовать асинхронные операции.

## Чем отличается

**Layered** организует вызовы по слоям, а **Clean / Hexagonal** дополнительно требует, чтобы внутренние правила не зависели от внешних технических деталей. В данном примере граница небольшая, но видна в `createChangeRankUseCase(repository)`.

## Как запустить

Откройте корень репозитория в VS Code и запустите **Live Server**. Перейдите к странице `architecture-patterns/clean/index.html`. Используется `<script type="module" src="main.js">`, поэтому прямое открытие через `file://` не рекомендуется.

В интерфейсе выберите бойца, задайте другое звание и нажмите **«Изменить звание»**. Сравните изменённую строку таблицы с журналом «Трассировка: кто вызвал кого?». При обновлении страницы данные возвращаются к исходным: в примере они изменяются только в памяти браузера, без записи на диск.

`index.html` задаёт элементы интерфейса, `style.css` отвечает за оформление, `data.js` содержит одинаковые для всех девяти примеров сведения об 11 вымышленных бойцах. Это общая учебная основа; архитектурные различия находятся в остальных файлах.
