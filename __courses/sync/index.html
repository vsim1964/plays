Стек вызовов и принцип LIFO

Противоречие возникает из-за того, что мы смешиваем порядок вызова функций с порядком их завершения. Стек вызовов (Call Stack) не определяет, какая функция должна быть вызвана первой. Порядок вызова определяется самим программным кодом.

Рассмотрим две принципиально разные ситуации.

1. Последовательный вызов функций

function first() {
    console.log("Первая");
}

function second() {
    console.log("Вторая");
}

function third() {
    console.log("Третья");
}

first();
second();
third();

Результат:

Первая
Вторая
Третья

Первая функция вызывается, полностью выполняется и её кадр удаляется из стека. Только после этого вызывается вторая функция, а после её завершения — третья. Функции не накапливаются в стеке. Каждая завершается до вызова следующей.

Этап 1
first()
→
Этап 2
second()
→
Этап 3
third()

Каждый кадр снимается со стека до появления следующего.

2. Вложенный вызов функций

Теперь изменим код так, чтобы первая функция вызывала вторую, а вторая — третью.

function first() {
    console.log("Начало первой");
    second();
    console.log("Конец первой");
}

function second() {
    console.log("Начало второй");
    third();
    console.log("Конец второй");
}

function third() {
    console.log("Начало третьей");
    console.log("Конец третьей");
}

first();

Результат:

Начало первой
Начало второй
Начало третьей
Конец третьей
Конец второй
Конец первой

Первая функция начинает выполняться первой. Но в процессе своего выполнения она вызывает вторую функцию. Первая функция ещё не завершила работу, поэтому её кадр остаётся в стеке. Вторая функция, в свою очередь, вызывает третью, также не завершив собственной работы. В результате в стеке одновременно находятся три незавершённых вызова.

Пошаговое выполнение программы

Call Stack
Консоль

Для простоты показаны только вызовы трёх пользовательских функций. Вызовы console.log() и контекст скрипта не показаны.

3. В чём смысл принципа LIFO

ДействиеПорядок
Начало выполнения функцийПервая, вторая, третья
Завершение выполнения функцийТретья, вторая, первая
Добавление кадров в стекПервая, вторая, третья
Удаление кадров из стекаТретья, вторая, первая

Принцип LIFO (Last In, First Out) относится именно к порядку добавления и удаления кадров вызовов из стека, а не к порядку начала выполнения функций.

Последняя из вложенных функций не первой начинает выполняться, а первой завершает своё выполнение.

Первая функция не может закончить свою работу, пока не завершится вызванная ею вторая функция, а вторая — пока не завершится вызванная ею третья. Никакого противоречия с принципом синхронного программирования здесь нет. Напротив, стек вызовов и служит механизмом организации такого выполнения.
