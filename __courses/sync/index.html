Асинхронное программирование в JavaScript

1. Стек вызовов и принцип LIFO

Противоречие возникает из-за того, что мы смешиваем порядок вызова функций с порядком их завершения. Стек вызовов (Call Stack) не определяет, какая функция должна быть вызвана первой. Порядок вызова определяется самим программным кодом.

Рассмотрим две принципиально разные ситуации.

1. Последовательный вызов функций

function first() {
    console.log("Первая");
}

function second() {
    console.log("Вторая");
}

function third() {
    console.log("Третья");
}

first();
second();
third();

Результат:

Первая
Вторая
Третья

Первая функция вызывается, полностью выполняется и её кадр удаляется из стека. Только после этого вызывается вторая функция, а после её завершения — третья. Функции не накапливаются в стеке. Каждая завершается до вызова следующей.

Этап 1
first()
→
Этап 2
second()
→
Этап 3
third()

Каждый кадр снимается со стека до появления следующего.

2. Вложенный вызов функций

Теперь изменим код так, чтобы первая функция вызывала вторую, а вторая — третью.

function first() {
    console.log("Начало первой");
    second();
    console.log("Конец первой");
}

function second() {
    console.log("Начало второй");
    third();
    console.log("Конец второй");
}

function third() {
    console.log("Начало третьей");
    console.log("Конец третьей");
}

first();

Результат:

Начало первой
Начало второй
Начало третьей
Конец третьей
Конец второй
Конец первой

Первая функция начинает выполняться первой. Но в процессе своего выполнения она вызывает вторую функцию. Первая функция ещё не завершила работу, поэтому её кадр остаётся в стеке. Вторая функция, в свою очередь, вызывает третью, также не завершив собственной работы. В результате в стеке одновременно находятся три незавершённых вызова.

Консоль

Для простоты показаны только вызовы трёх пользовательских функций. Вызовы console.log() и контекст скрипта не показаны.

3. В чём смысл принципа LIFO

ДействиеПорядок
Начало выполнения функцийПервая, вторая, третья
Завершение выполнения функцийТретья, вторая, первая
Добавление кадров в стекПервая, вторая, третья
Удаление кадров из стекаТретья, вторая, первая

Принцип LIFO (Last In, First Out) относится именно к порядку добавления и удаления кадров вызовов из стека, а не к порядку начала выполнения функций.

Последняя из вложенных функций не первой начинает выполняться, а первой завершает своё выполнение.

Первая функция не может закончить свою работу, пока не завершится вызванная ею вторая функция, а вторая — пока не завершится вызванная ею третья. Никакого противоречия с принципом синхронного программирования здесь нет. Напротив, стек вызовов и служит механизмом организации такого выполнения.

2. Как работает цикл событий (Event Loop)

Допустим, программист написал пять функций и последовательно вызывает их. В третьей функции предусмотрена операция, которую необходимо выполнить с задержкой. Посмотрим, как в этом случае распределяется работа между движком JavaScript и браузером.

function first() {
    console.log("Первая функция");
}

function second() {
    console.log("Вторая функция");
}

function third() {
    setTimeout(function task() {
        console.log("Отложенная операция");
    }, 2000);
}

function fourth() {
    console.log("Четвёртая функция");
}

function fifth() {
    console.log("Пятая функция");
}

first();
second();
third();
fourth();
fifth();

От стека вызовов к отложенной операции

Движок JavaScript начинает выполнение обычного скрипта, создаёт глобальный контекст выполнения и помещает его в стек вызовов. Контекст выполнения — это служебная информация, необходимая для исполнения данного участка кода. Затем движок вызывает первую функцию, помещает её контекст поверх глобального, выполняет её и снимает её контекст со стека. В том же порядке выполняется вторая функция.

При выполнении третьей функции движок встречает setTimeout(). Посредством этой функции программист поручает браузеру вызвать функцию task() через заданный промежуток времени. Браузер регистрирует таймер и сохраняет ссылку на переданную ему функцию. Движок не ждёт истечения времени: вызов setTimeout() завершается, затем завершается третья функция, после чего выполняются четвёртая и пятая.

Функция setTimeout() предоставляется браузером, а не самим языком JavaScript. Подобные функции, методы и объекты, посредством которых JavaScript обращается к механизмам браузера, называются Web APIs (программные интерфейсы браузера). В данном примере используется интерфейс доступа к механизму таймеров. Сам таймер отслеживает время, но не исполняет тело функции task().

От таймера к очереди задач

Тем временем браузер отслеживает истечение заданного времени. Когда оно истекло, браузер помещает в очередь задач (Task Queue) поручение вызвать зарегистрированную функцию. Если движок JavaScript ещё занят выполнением кода, задача остаётся в очереди. Функция task() до этого момента вообще не вызывалась: в стеке не было её контекста, поэтому и переносить его из стека в очередь не требовалось.

Когда выполнение текущей задачи завершится и стек освободится, среда выполнения, после обработки накопившихся микрозадач, сможет выбрать следующую обычную задачу. Движок вызовет соответствующую функцию, создаст её контекст выполнения, поместит его в стек и выполнит содержащиеся в ней инструкции. Микрозадачи — особый вид отложенных задач; подробно мы познакомимся с ними при изучении Promise.

Этот циклически повторяющийся процесс обработки задач называется Event Loop (цикл событий). Event Loop — не отдельный исполнитель кода, а алгоритм работы среды выполнения, который организует переход от завершившейся задачи к следующей.

При обычных условиях результат будет следующим:

Первая функция
Вторая функция
Четвёртая функция
Пятая функция
Отложенная операция

Последнее сообщение появится примерно через две секунды после регистрации таймера или позднее, если основной поток занят.

Асинхронность становится возможной благодаря разделению двух процессов: ожидания наступления определённого события и исполнения JavaScript-кода после наступления этого события. Первым в нашем примере занимается механизм таймеров браузера, вторым — движок JavaScript.
