# **Асинхронное программирование в JavaScript**

## **Синхронное и асинхронное выполнение кода**

До сих пор, изучая JavaScript, мы преимущественно имели дело с синхронным выполнением программного кода. Смысл такого выполнения состоит в том, что каждая следующая операция начинается после завершения предыдущей. Если мы вызываем функцию, JavaScript выполняет инструкции, содержащиеся в её теле, возвращает результат и только после этого переходит к выполнению инструкции, следующей за вызовом функции. Продолжительность выполнения отдельной операции не меняет этого порядка.

Допустим, мы разрабатываем приложение, которое получает сведения о странах Европы из JSON-файла, находящегося на сервере. Чтобы отобразить таблицу стран, необходимо отправить запрос серверу, дождаться ответа, получить данные, обработать их и создать соответствующие элементы HTML. Между отправкой запроса и получением данных может пройти несколько миллисекунд, несколько секунд или даже несколько минут. Продолжительность ожидания зависит от скорости соединения, загруженности сервера, объёма передаваемых данных и множества других обстоятельств, которые программист не может контролировать.

Операцию, которая препятствует выполнению другого кода до своего завершения, называют **блокирующей операцией (blocking operation)**. Для браузерных приложений продолжительные блокирующие операции особенно нежелательны, поскольку нарушают взаимодействие пользователя с интерфейсом.

**Асинхронное программирование** предлагает иной способ организации работы приложения. Вместо того чтобы запустить операцию и остановить выполнение программы до получения результата, мы запускаем операцию, предусматриваем дальнейшую обработку её результата и продолжаем выполнение другого кода. Когда операция завершается, программа получает возможность обработать её результат.

**Асинхронное программирование (asynchronous programming)** — способ организации программного кода, при котором запуск операции и обработка её результата могут быть разделены во времени, а ожидание завершения операции не блокирует выполнение других задач.

## **Когда необходимо асинхронное программирование**

В практической разработке мы постоянно сталкиваемся с операциями, момент завершения которых заранее неизвестен или выполнение которых необходимо отложить. К ним относятся:

* получение данных с сервера;
* загрузка JSON-файлов;
* отправка данных на сервер;
* чтение и запись файлов асинхронными средствами Node.js;
* обращение к базам данных;
* работа с таймерами;
* ожидание пользовательских событий.


`Promise` — объект, представляющий результат операции, которая может завершиться позднее.
`new Promise()` — средство самостоятельного создания такого объекта. Используется, когда операция сама не возвращает `Promise`, как, например, `setTimeout()`. Если функция уже возвращает `Promise`, как `fetch()`, создавать его дополнительно не нужно.
`await` — оператор ожидания результата `Promise`. Он приостанавливает выполнение окружающей функции, но не блокирует основной поток. Если ему передать обычное значение, оно автоматически преобразуется в `Promise`. Однако блокирующая операция от этого неблокирующей не становится.
`async` — ключевое слово, которое позволяет использовать `await` внутри функции и гарантирует, что при вызове эта функция сама вернёт `Promise`, даже если мы явно его не создавали.

```js
async function task() {
    await new Promise(resolve => setTimeout(resolve, 2000));
    console.log("Готово");
}
```

В данном примере создаются два объекта `Promise`: один явно, посредством `new Promise()`, для ожидания таймера, другой автоматически, благодаря `async`, для представления результата работы всей функции `task()`.
Запомнить можно так: `new Promise()` **создаёт,** `await` **ожидает,** `async` **разрешает ожидание внутри функции и гарантирует возвращение собственного** `Promise`**.**
