В этом уроке изучается view.js из проекта MVC Fighters, а не библиотека Vue.js. Все семь функций и их исходный код соответствуют прочитанному файлу репозитория. В лаборатории используются отдельные демонстрационные данные, а не содержимое исходного JSON.

1. Место представления в приложении

MVC (Model–View–Controller) — способ разделить обязанности частей программы. Модель хранит и обрабатывает данные, представление работает с пользовательским интерфейсом, контроллер связывает их.

fighters.json → data.js → model.js → controller.js → view.js → DOM

Это схема первоначального потока данных, а не единственное направление взаимодействия. При вводе текста сведения движутся обратно: из DOM через представление в контроллер, затем в модель. Само представление не загружает JSON и не сортирует бойцов.

Рендерингом называют построение или обновление видимого представления данных. В этом проекте данные превращаются в строки HTML-таблицы.

2. Что происходит при загрузке модуля

Браузер разбирает HTML и создаёт DOM (Document Object Model) — дерево объектов, соответствующих структуре документа. Глобальный объект document предоставляет доступ к этому дереву. Он принадлежит браузерной среде, поэтому импортировать его не нужно.

const tbody = document.querySelector("#fighters");
const searchInput = document.querySelector("#search");
const rankSelect = document.querySelector("#rank");
const sortSelect = document.querySelector("#sort");
const reloadButton = document.querySelector("#reload");
const counter = document.querySelector("#counter");
const status = document.querySelector("#status");
const emptyMessage = document.querySelector("#empty");

Метод querySelector() возвращает первый DOM-элемент, соответствующий CSS-селектору. Символ # означает поиск по идентификатору id. Например, в исходном HTML находится:

<tbody id="fighters"></tbody>

В переменной tbody сохраняется ссылка на этот объект, а не строка HTML и не массив бойцов. const запрещает переназначать привязку, но не запрещает менять свойства самого объекта. Если элемент отсутствует, querySelector() возвращает null.

3. Почему в view.js нет импортов

Импорт даёт модулю доступ к экспортированным значениям другого модуля. Передача аргументов — другой механизм: функция получает конкретные значения в момент вызова. Контроллер импортирует функции представления, а затем передаёт им данные.

// view.js
export function renderFighters(fighters) {
  // ...
}

// controller.js (сокращённый фрагмент)
import { renderFighters } from "./view.js";
// ...
renderFighters(visible);

visible — аргумент, то есть значение, переданное при вызове; fighters — параметр, локальное имя этого значения внутри функции. При передаче массива новый массив автоматически не создаётся: функция получает значение ссылки на тот же массив. Здесь она читает его, не изменяя.

Представление получает информацию из двух источников: из DOM (поля ввода и элементы страницы) и через аргументы, переданные контроллером. export позволяет другим модулям импортировать функцию, но не вызывает её.

4. Семь функций view.js

4.1. readFilters() — чтение фильтров

export function readFilters() {
  return {
    search: searchInput.value,
    rank: rankSelect.value,
    sort: sortSelect.value,
  };
}

Функция не принимает аргументов. Она обращается к трём ранее найденным DOM-объектам. Свойство value возвращает текущее значение поля ввода или выбранного пункта списка. У списка это значение атрибута value выбранной опции, а не обязательно видимая надпись.

{ search: "Москва", rank: "сержант", sort: "ageAsc" }

Это пример объекта, который создаётся при вызове. return завершает функцию и возвращает объект контроллеру, где он сохраняется в переменной filters. Пустая строка означает отсутствие ограничения по соответствующему полю. Функция только читает данные; отбор бойцов выполняет модель.

4.2. bindEvents() — регистрация обработчиков

export function bindEvents(onFilterChange, onReload) {
  searchInput.addEventListener("input", onFilterChange);
  rankSelect.addEventListener("change", onFilterChange);
  sortSelect.addEventListener("change", onFilterChange);
  reloadButton.addEventListener("click", onReload);
}

Событие — уведомление браузера о произошедшем действии. Обработчик события — функция, которую браузер вызывает при наступлении этого события. Метод addEventListener() регистрирует такую функцию на элементе.

// controller.js
bindEvents(updateScreen, reloadData);

Контроллер передаёт две функции как значения, без круглых скобок. Внутри bindEvents() они получают имена onFilterChange и onReload. Событие input возникает при пользовательском изменении текста; change — при изменении выбранного пункта; click — при активации кнопки. При регистрации обработчики не вызываются. Позднее браузер вызывает их и передаёт объект события, который эти функции контроллера не используют. Результат работы bindEvents — зарегистрированные обработчики, а не возвращённые данные.

4.3. renderRanks(ranks) — заполнение списка званий

export function renderRanks(ranks) {
  const previousRank = rankSelect.value;
  rankSelect.replaceChildren(new Option("Все звания", ""));
  for (const rank of ranks) rankSelect.add(new Option(rank, rank));
  rankSelect.value = ranks.includes(previousRank) ? previousRank : "";
}

Контроллер вызывает renderRanks(getRanks()), передавая массив званий из модели. Сначала запоминается текущий выбор в previousRank. Метод replaceChildren() заменяет все дочерние элементы списка одной новой опцией. new Option(текст, значение) создаёт объект HTML-элемента option. Первый аргумент виден пользователю, второй доступен через value.

Цикл for...of последовательно перебирает значения массива. Для каждого звания создаётся пункт, который метод add() добавляет в select. Затем includes() проверяет, есть ли прежнее звание в новом массиве. Условное выражение условие ? значение1 : значение2 сохраняет прежний выбор, если он ещё существует, иначе выбирает пустое значение («Все звания»). Функция обновляет DOM, а не массив званий.

4.4. renderFighters(fighters) — создание таблицы

export function renderFighters(fighters) {
  tbody.replaceChildren();

  fighters.forEach((fighter, index) => {
    const row = document.createElement("tr");
    const values = [
      index + 1,
      fighter.name,
      fighter.age,
      fighter.draftCity,
      fighter.rank,
      fighter.role,
    ];

    for (const value of values) {
      const cell = document.createElement("td");
      cell.textContent = value;
      row.append(cell);
    }
    tbody.append(row);
  });

  emptyMessage.hidden = fighters.length !== 0;
  console.log("[VIEW] Нарисовано строк таблицы:", fighters.length);
}

Контроллер передаёт массив visible — результат отбора и сортировки в модели. Сначала tbody.replaceChildren() удаляет прежние строки. Заголовки таблицы находятся в thead и не удаляются.

Метод массива forEach() вызывает переданную стрелочную функцию для каждого бойца. Такая функция, переданная другой функции для последующего вызова, называется callback (функция обратного вызова). fighter получает очередной объект, index — его порядковый индекс, начиная с нуля.

document.createElement("tr") создаёт новую строку таблицы в памяти. Она ещё не вставлена в документ. Массив values определяет порядок шести ячеек. index + 1 превращает индекс в привычный номер строки; остальные пять значений читаются из свойств объекта бойца. Это массив значений одной строки, а не массив бойцов.

Внутренний цикл for...of перебирает эти шесть значений. Для каждого создаётся ячейка td, свойство textContent записывает значение как текст (а не интерпретирует его как HTML), метод row.append(cell) добавляет ячейку к строке. После завершения внутреннего цикла tbody.append(row) присоединяет готовую строку к таблице. Внешний перебор повторяет процесс для каждого бойца.

<tr>
  <td>1</td>
  <td>Алексей Петров</td>
  <td>28</td>
  <td>Москва</td>
  <td>сержант</td>
  <td>командир отделения</td>
</tr>

Это пример результата для одного объекта. При пустом массиве ни одна строка не создаётся. Выражение fighters.length !== 0 возвращает true, если массив не пуст, и false, если пуст. Присваивание свойству hidden скрывает сообщение об отсутствии результатов при наличии бойцов и показывает его при пустом массиве. Последняя инструкция записывает количество строк в консоль разработчика. Функция не возвращает таблицу контроллеру: она непосредственно изменяет DOM.

4.5. renderCounter(visible, total) — счётчик

export function renderCounter(visible, total) {
  counter.textContent = `Показано: ${visible} из ${total}`;
}

Контроллер вызывает renderCounter(visible.length, getTotalCount()). Здесь параметр visible — число, несмотря на то что одноимённая переменная контроллера содержит массив. Обратные кавычки образуют шаблонную строку; выражения внутри ${...} вычисляются и подставляются в текст. При аргументах 3 и 10 на странице появляется «Показано: 3 из 10». Функция не вычисляет общее количество самостоятельно.

4.6. showStatus(message, isError) — состояние загрузки

export function showStatus(message, isError = false) {
  status.textContent = message;
  status.classList.toggle("error", isError);
}

Параметр message получает текст от контроллера. Второй параметр имеет значение по умолчанию false, если аргумент не передан или равен undefined. classList предоставляет доступ к CSS-классам элемента; toggle("error", isError) добавляет класс error при true и удаляет при false. Сам вид ошибки определяется CSS. Например, showStatus("Ошибка загрузки", true) меняет текст и добавляет класс ошибки. Функция не определяет причину ошибки: это обязанность контроллера.

4.7. setLoading(loading) — состояние кнопки

export function setLoading(loading) {
  reloadButton.disabled = loading;
  reloadButton.textContent = loading ? "Загрузка…" : "Загрузить JSON заново";
}

Контроллер передаёт логическое значение true в начале загрузки и false при её завершении. Свойство disabled делает кнопку недоступной при true. Условное выражение выбирает одну из двух надписей. Это изменение интерфейса, а не запуск загрузки. Сама загрузка происходит в модели и слое данных по команде контроллера.

6. Полная последовательность операций

Первоначальная загрузка

// controller.js
export function startController() {
  bindEvents(updateScreen, reloadData);
  reloadData();
}

HTML подключает main.js как модуль. При загрузке цепочки модулей вычисляется view.js: находятся восемь DOM-элементов, становятся доступны экспортированные функции. После запуска контроллера он регистрирует обработчики через bindEvents, затем вызывает reloadData.

async function reloadData() {
  setLoading(true);
  showStatus("Читаем fighters.json…");
  try {
    await loadFighters();
    renderRanks(getRanks());
    updateScreen();
    showStatus("Данные успешно загружены из JSON");
  } catch (error) {
    console.error("[CONTROLLER] Ошибка загрузки:", error);
    showStatus("Ошибка: " + error.message, true);
  } finally {
    setLoading(false);
  }
}
  1. Кнопка блокируется, надпись меняется.
  2. Появляется сообщение о чтении JSON.
  3. Контроллер ожидает завершения загрузки модели (await loadFighters()).
  4. Контроллер получает звания и передаёт их renderRanks.
  5. updateScreen вызывает readFilters, получает объект фильтров и передаёт значения модели.
  6. Модель возвращает отобранный массив, контроллер вызывает renderFighters и renderCounter.
  7. Появляется сообщение об успехе.
  8. Блок finally в любом случае восстанавливает кнопку.

При ошибке управление переходит в catch, который сообщает об ошибке в консоль и вызывает showStatus с true. Остальные операции внутри try после места ошибки пропускаются. finally исполняется и при успехе, и при ошибке. В данном коде setLoading(true) и первое showStatus стоят перед try.

Изменение фильтра или сортировки

function updateScreen() {
  const filters = readFilters();
  const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);

  console.log("[CONTROLLER] Обновляем представление");
  renderFighters(visible);
  renderCounter(visible.length, getTotalCount());
}
Событие DOM → updateScreen → readFilters → model → renderFighters → renderCounter

При каждом изменении поиска, звания или сортировки браузер вызывает updateScreen. Контроллер читает все три поля, получает от модели новый набор видимых бойцов и обновляет таблицу и счётчик. JSON заново не загружается, список званий не перестраивается, статус и кнопка не меняются.

Повторная загрузка

Нажатие кнопки вызывает reloadData. Снова выполняется цепочка загрузки, заполнения званий и обновления таблицы. Обработчики повторно не регистрируются: bindEvents вызывается при запуске контроллера, а не внутри reloadData.

Порядок объявлений функций в файле не равен порядку их выполнения. View.js не содержит центрального алгоритма, который по очереди вызывает семь функций. Последовательностью управляет контроллер, а новые циклы работы запускают события браузера.

7. Интерактивная лаборатория

Здесь воспроизведены семь функций представления с отдельными демонстрационными данными. Поиск, сортировка, звания и кнопка работают. Учебная консоль показывает действия контроллера и представления. Повторная загрузка имитируется локально; сетевого запроса к JSON нет.

8. Самопроверка
Почему view.js не нужен import?
DOM доступен через браузерный document, остальные значения поступают через параметры функций, вызываемых контроллером.
Что хранится в searchInput?
Ссылка на DOM-объект поля ввода. Текст поля получается через searchInput.value.
Почему bindEvents получает updateScreen без скобок?
Передаётся сама функция для будущего вызова браузером. Скобки вызвали бы её сразу.
Почему renderFighters не использует return?
Её полезный результат — изменения DOM. Возвращать массив или таблицу контроллеру не требуется.
Почему при поиске не загружается JSON?
Обработчик поиска вызывает updateScreen, а не reloadData. Модель обрабатывает ранее загруженный массив.
Что произойдёт, если массив fighters пуст?
Старые строки будут удалены, forEach не вызовет callback, сообщение #empty станет видимым.
Источники: view.js · controller.js · index.html. Лаборатория — самостоятельная учебная имитация.
