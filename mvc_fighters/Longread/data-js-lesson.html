РАЗДЕЛ 01

Какую задачу решает модуль DATA

Приложению нужна таблица бойцов отделения. Сами сведения лежат в файле fighters.json. Функция fetchFighters() получает файл через HTTP, читает его содержимое, проверяет, что в поле squad находится массив, и отдаёт этот массив остальной программе.

→

Это слой доступа к данным — Data Layer. Он не рисует HTML-таблицу и не решает, какие столбцы показывать. Его работа заканчивается передачей массива вызывающему коду.

Слова «получить данные», «вернуть результат» и «передать массив» здесь имеют точное техническое значение. Ниже разберём, какие объекты создаются и куда они попадают.
РАЗДЕЛ 02

Синхронная и асинхронная работа

Синхронный код выполняет инструкции по порядку: пока текущая инструкция не завершилась, следующая в том же потоке выполнения не начинается. Асинхронная операция может начаться сейчас, а завершиться позднее; JavaScript не обязан блокировать всю программу, пока ждёт её результата.

console.log('Первое');
console.log('Второе');
console.log('Третье');
console.log('Начало');
setTimeout(() => {
  console.log('Таймер завершён');
}, 2000);
console.log('Продолжение');

В правом примере сообщение «Продолжение» появится раньше «Таймер завершён». Вызов setTimeout() назначает действие на будущее и сразу позволяет выполнять следующий код.

РАЗДЕЛ 03

Promise — объект, представляющий будущее завершение

Когда вызывается fetch(), сервер ещё может не ответить. Поэтому функция сразу предоставляет объект Promise. Это объект, с которым связаны будущий результат операции или причина её неудачи.

pendingОперация пока не завершилась
fulfilledОперация успешно завершилась
rejectedОперация завершилась ошибкой

Один Promise проходит только один из двух путей: pending → fulfilled либо pending → rejected. Одновременно в двух конечных состояниях он не бывает.

ЛАБОРАТОРИЯ 02 · Настоящий Promise с задержкой
async function getNumber(fail = false) {
  await new Promise((resolve, reject) => {
    setTimeout(() => {
      if (fail) reject(new Error('Число не получено'));
      else resolve();
    }, 2000);
  });
  return 5;
}

const result = getNumber(false);
result.then(value => console.log(value))
      .catch(error => console.log(error.message));
Ещё не вызван
Нажмите кнопку, чтобы увидеть переход состояний.

В лаборатории используется настоящий Promise и настоящий setTimeout. Состояние показывается по этапам, а не через раскрытие объекта в DevTools.

Что означает result.then()?

Метод .then() есть у Promise. Вызов result.then(функция) регистрирует функцию-обработчик, которую JavaScript вызовет после успешного завершения Promise. В параметр value будет передан результат — например, число 5.

result.then((value) => {
  console.log('Получено:', value);
});

Название value выбирает программист. Это параметр стрелочной функции, а не специальное слово JavaScript. Для ошибки можно передать второй обработчик в then() или использовать .catch(). Сам метод then() тоже возвращает новый Promise.

РАЗДЕЛ 04

Когда нужны async и await

async перед объявлением функции означает, что каждый её вызов возвращает Promise. Объявление функции само по себе Promise не создаёт: он появляется при вызове. Даже если тело функции содержит только return 5, вызывающий код получает Promise, успешно завершающийся со значением 5.

function getNumber() {
  return 5;
}
const x = getNumber();
// x — число 5
async function getNumber() {
  return 5;
}
const x = getNumber();
// x — Promise

await означает: приостановить выполнение текущей асинхронной функции, пока ожидаемый Promise не завершится, и затем получить его значение. Браузер в целом не останавливается.

const promise = fetch('./fighters.json');
// promise — объект Promise

const response = await fetch('./fighters.json');
// response — объект Response после успешного ожидания

await требуется не для каждой строки внутри async, а тогда, когда дальнейшие действия зависят от результата асинхронной операции. Допускается также await на верхнем уровне JavaScript-модулей. Формально await можно применять и к обычному значению, но в таком примере это ни к чему.

РАЗДЕЛ 05

Что значит «функция возвращает»?

Это не образное выражение. Когда код вызывает функцию, она может вычислить значение и посредством return передать его в место вызова. Затем вызывающая инструкция использует полученное значение.

function getNumber() {
  return 5;
}
const result = getNumber();
// Здесь результат вызова getNumber() — число 5.

В случае async function в место вызова поступает Promise. Само значение return 5 становится результатом его успешного завершения. Если вызывающий код пишет await getNumber(), то получает уже число 5, а не Promise.

Функция возвращает значение не «браузеру вообще» и не «в консоль», а туда, где стоит выражение её вызова. Записать это значение в переменную, вывести в консоль или передать другой функции решает вызывающий код.
РАЗДЕЛ 06

fetch() и объект Response

const response = await fetch('./fighters.json', {
  cache: 'no-store'
});

fetch() — встроенная браузерная функция, которая запускает HTTP-запрос и возвращает Promise. При успешном выполнении запроса Promise даёт объект Response. Этот объект представляет HTTP-ответ: его статус, заголовки и тело.

response — имя переменной, выбранное программистом. Можно было написать answer или serverReply. Но тогда и дальше нужно писать answer.ok или serverReply.ok. А вот ok, status и json() — стандартные имена свойств и методов интерфейса Response.

response.okСвойство: true при HTTP-статусе 200–299, иначе false.
response.statusСвойство: числовой код HTTP-ответа, например 200 или 404.
response.json()Метод: читает тело HTTP-ответа, разбирает JSON и возвращает Promise.

Круглые скобки после json() показывают вызов метода. После свойства ok скобок нет: мы только читаем его значение. Параметр cache: 'no-store' просит браузер не пользоваться HTTP-кешем для этого запроса и не сохранять ответ в нём.

ЛАБОРАТОРИЯ 03 · Имя переменной и свойства Response

Меняется только придуманное нами имя переменной. Названия ok и status остаются неизменными.

РАЗДЕЛ 07

Проверка ответа: if, !, new Error и throw

if (!response.ok) {
  throw new Error(
    `HTTP ${response.status}: не удалось получить fighters.json`
  );
}

if проверяет условие. ! означает логическое отрицание: !response.ok истинно, если HTTP-ответ неуспешен. Error — встроенный класс, new Error('...') создаёт объект ошибки. Само создание ошибки программу не прерывает. Оператор throw выбрасывает исключение и прерывает обычное выполнение текущего участка кода.

Внутри async-функции неперехваченное исключение приводит к состоянию rejected у Promise этой функции. В записи с обратными кавычками `HTTP ${response.status}: ...` часть ${response.status} подставляет код ответа в строку.

ЛАБОРАТОРИЯ 04 · Проверяем HTTP-статус
Выберите статус и нажмите кнопку.

Это модель стандартных свойств Response. Даже при HTTP 404 fetch() обычно успешно получает объект Response; именно проверка ok превращает такой статус в исключение приложения.

РАЗДЕЛ 08

response.json(): от текста к данным JavaScript

const data = await response.json();

HTTP-ответ содержит тело с текстом JSON. Метод response.json() читает это тело и разбирает JSON, получая значение JavaScript. В нашем примере — объект со свойством squad. Поскольку чтение тела тоже асинхронно, метод возвращает Promise, и здесь снова нужен await.

Текст JSON:

{
  "squad": [
    {"name": "Алексей", "rank": "сержант"},
    {"name": "Иван", "rank": "рядовой"}
  ]
}

Значение JavaScript:

data.squad[0].name
// "Алексей"

data.squad.length
// 2

Обычно response.json() используют один раз: тело Response после чтения считается использованным. Если JSON имеет неверный синтаксис, разбор завершится ошибкой. Сам метод json() ещё не проверяет, действительно ли там массив бойцов.

РАЗДЕЛ 09

Array.isArray(data.squad): проверяем структуру

if (!Array.isArray(data.squad)) {
  throw new Error('Неверный формат JSON: ожидается массив squad');
}

Array — встроенный конструктор массивов. isArray() — его статический метод, который определяет, является ли переданное значение массивом. Например, Array.isArray([1, 2]) возвращает true, а Array.isArray({name: 'Иван'}) — false.

Здесь метод получает аргумент data.squad. Если это не массив, оператор ! делает условие истинным и выбрасывается ошибка. Эта проверка ничего не говорит о правильности полей внутри каждого бойца.

РАЗДЕЛ 10

console.log(): для чего [DATA] в квадратных скобках

console.log('[DATA] JSON получен:', data);

console — встроенный объект для диагностических сообщений; log() — его метод. Ему переданы два аргумента: строка '[DATA] JSON получен:' и переменная data. Запятая разделяет аргументы метода.

[DATA] — обычный текст внутри кавычек, а не команда и не свойство языка. Автор сам придумал эту метку, чтобы отличать сообщение слоя данных от других сообщений. Аналогично можно использовать метки [MODEL] или [VIEW]. console.log() выводит сведения разработчику в консоль, но не создаёт элементы HTML-таблицы.

РАЗДЕЛ 11

return data.squad: что именно передаётся дальше

return data.squad;

Объект data содержит свойство squad. В этом свойстве находится массив. Команда return data.squad завершает функцию и задаёт значение, с которым успешно завершится Promise, возвращённый fetchFighters().

// В другом модуле:
const fighters = await fetchFighters();
console.log(fighters);
// Здесь fighters — массив объектов бойцов.

Если убрать await, переменная fighters получит Promise, а не массив. Если запрос или проверка завершатся исключением, Promise будет отклонён, поэтому вызывающему коду следует предусмотреть обработку ошибки, например через try...catch.

Модуль DATA знает, откуда взять данные и как проверить структуру ответа. Контроллер организует последовательность операций: вызывает fetchFighters(), ждёт массив и передаёт его дальше. Представление (View) преобразует массив в элементы HTML, которые увидит пользователь.

// Пример координирующего кода:
import { fetchFighters } from './data.js';
import { renderFighters } from './view.js';

async function start() {
  try {
    const fighters = await fetchFighters();
    renderFighters(fighters);
  } catch (error) {
    console.error('Не удалось построить таблицу:', error);
  }
}

start();

Здесь renderFighters() показана как пример функции слоя представления. Её реализация должна находиться в другом модуле. Сама fetchFighters() никакой таблицы не создаёт.

ПОЛНЫЙ РАЗБОР

Весь исходный модуль — с краткими комментариями

// DATA: слой получения данных.
// fighters.json имитирует ответ сервера.
export async function fetchFighters() {
  // fetch возвращает Promise.
  // await даёт объект Response после успешного ожидания.
  const response = await fetch('./fighters.json', {
    cache: 'no-store'
  });

  // ok — свойство Response, а не метод.
  if (!response.ok) {
    // new Error создаёт объект ошибки;
    // throw выбрасывает исключение.
    throw new Error(
      `HTTP ${response.status}: не удалось получить fighters.json`
    );
  }

  // json() возвращает Promise с разобранными данными.
  const data = await response.json();

  // Проверяем, что squad — массив.
  if (!Array.isArray(data.squad)) {
    throw new Error('Неверный формат JSON: ожидается массив squad');
  }

  // Сообщение разработчику; [DATA] — текстовая метка.
  console.log('[DATA] JSON получен:', data);

  // Массив становится результатом Promise этой async-функции.
  return data.squad;
}
Практическое условие: для настоящего запроса fetch('./fighters.json') откройте страницу через локальный HTTP-сервер (например, Live Server), а не напрямую через file://. Демонстрации в этом лонгриде используют данные внутри страницы и работают без сервера.

Что может пойти не так

Ошибка сети отклонит Promise, возвращаемый fetch(). HTTP 404 сам по себе обычно не отклоняет Promise от fetch(), поэтому нужна проверка response.ok. Неверный JSON вызовет ошибку при response.json(). А корректный JSON с полем squad неправильного типа не пройдёт проверку Array.isArray().
