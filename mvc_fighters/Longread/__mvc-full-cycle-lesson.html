Мы уже изучили data.js, view.js, model.js и controller.js по отдельности. Теперь рассмотрим их как единую программу. Исходные фрагменты взяты из проекта mvc_fighters. В лабораториях сетевой запрос имитируется, чтобы учебник работал автономно.

1. Карта проекта

В проекте существует восемь файлов с разными обязанностями. Само по себе наличие файлов в одной папке не заставляет их выполняться: браузеру требуется точка входа и явные связи между модулями.

ФайлОтветственностьЧто передаёт

style.cssПравила оформленияCSS браузеру

Различайте три схемы: зависимости файлов (кто кого импортирует), последовательность вызовов (кто запускает функцию) и движение данных (кто кому передаёт значения). Они не совпадают.

fighters.json→data.js→model.js→controller.js→view.js→DOM

Это путь массива при первоначальной загрузке, а не порядок импорта модулей.

2. Что происходит при открытии index.html

При обычном запуске проекта через локальный HTTP-сервер браузер запрашивает index.html. Он разбирает полученный текст, создаёт DOM (объектную модель документа) и запрашивает связанные ресурсы. В заголовке исходного документа находятся две важные инструкции:

<link rel="stylesheet" href="./style.css">
<script type="module" src="./main.js"></script>

Первая подключает правила оформления. Вторая объявляет main.js модулем JavaScript. Модуль — файл с собственной областью имён, который может импортировать и экспортировать значения. В отличие от классического скрипта без defer, такой модуль по умолчанию выполняется после разбора HTML, когда его зависимости готовы. Скачивание зависимостей и разбор страницы могут идти параллельно; не следует представлять сетевые запросы как строго последовательную цепочку.

<tbody id="fighters"></tbody>
<strong id="counter">Бойцов: —</strong>
<span id="status" role="status" aria-live="polite">Ожидание загрузки…</span>

Здесь уже есть структура будущей таблицы, но нет строк с бойцами. Браузер может отобразить исходную разметку, пока выполняется запрос данных. Модель данных и DOM — две разные структуры в памяти. CSS не загружает бойцов и не вызывает функции JavaScript.

Для самого проекта используйте HTTP-сервер (например, Live Server в VS Code). При открытии index.html через file:// браузер может блокировать модульные импорты и fetch(). Этот учебный HTML не требует сервера.

3. Граф импортов: как браузер узнаёт о других файлах

В index.html подключён только main.js. Остальные файлы браузер обнаруживает по инструкциям import. Импорт предоставляет модулю доступ к экспортированным значениям другого модуля; он не означает автоматического вызова импортированной функции.

index.html
└── main.js
    └── controller.js
        ├── model.js
        │   └── data.js
        └── view.js
// main.js
import { startController } from "./controller.js";

// controller.js
import { loadFighters, getRanks, getTotalCount, getVisibleFighters } from "./model.js";
import { bindEvents, readFilters, renderRanks, renderFighters, renderCounter, showStatus, setLoading } from "./view.js";

// model.js
import { fetchFighters } from "./data.js";

В data.js и view.js импортов нет. data.js использует предоставляемый браузером fetch(), view.js — document. fighters.json не входит в граф импортов: его запрашивает функция fetchFighters() позднее, во время выполнения.

Браузер загружает модули, связывает их экспортируемые и импортируемые имена и затем выполняет код. Для данного графа зависимости выполняются раньше модулей, которые от них зависят. Каждый модуль с одним и тем же разрешённым URL в пределах данного документа обычно вычисляется один раз.

4. Что выполняется до первой строки main.js

У модулей есть код верхнего уровня (инструкции вне функций) и тела функций. Объявление функции делает её доступной для вызова, но не выполняет её тело.

// model.js
let fighters = [];

// view.js
const tbody = document.querySelector("#fighters");
const searchInput = document.querySelector("#search");
const rankSelect = document.querySelector("#rank");
const sortSelect = document.querySelector("#sort");
const reloadButton = document.querySelector("#reload");
const counter = document.querySelector("#counter");
const status = document.querySelector("#status");
const emptyMessage = document.querySelector("#empty");

В model.js создаётся пустой массив. В view.js восемь переменных получают ссылки на уже существующие DOM-элементы. В data.js и controller.js объявлены функции, но запрос JSON и обновление экрана ещё не начались. Переменная fighters принадлежит области имён model.js и напрямую не экспортируется. Контроллер получает доступ к данным через функции модели.

5. main.js — точка входа

// Точка входа: HTML загружает только этот JS-модуль.
import { startController } from "./controller.js";

console.log("[MAIN] Запуск приложения MVC");
startController();

Точка входа (entry point) — модуль, с которого запускается прикладная логика. Импорт предоставляет ссылку на функцию startController, console.log выводит сообщение, а круглые скобки в последней строке вызывают функцию. Аргументов нет; никаких данных о бойцах main.js не получает. Он передаёт управление контроллеру, а не массив.

Вызов startController() синхронный: он выполняет свои инструкции до завершения. Внутри него запускается асинхронная функция reloadData(), но её Promise не возвращается и не ожидается в main.js. Поэтому окончание выполнения main.js не означает окончания загрузки JSON.

6. Контроллер начинает работу

export function startController() {
  bindEvents(updateScreen, reloadData);
  reloadData();
}

Сначала контроллер передаёт представлению две функции как значения. Обратите внимание: updateScreen и reloadData без круглых скобок — ссылки на функции. Представление регистрирует их как обработчики событий (callback, функция, которую вызовут позднее).

export function bindEvents(onFilterChange, onReload) {
  searchInput.addEventListener("input", onFilterChange);
  rankSelect.addEventListener("change", onFilterChange);
  sortSelect.addEventListener("change", onFilterChange);
  reloadButton.addEventListener("click", onReload);
}

Теперь браузер знает, какую функцию нужно вызвать при вводе текста, изменении списков и клике по кнопке. Регистрация не вызывает обработчики. Затем контроллер сам вызывает reloadData() для первой загрузки. Это отдельный вызов, не событие click.

7. Асинхронная цепочка: запрос и возвращение массива

async function reloadData() {
  setLoading(true);
  showStatus("Читаем fighters.json…");
  try {
    await loadFighters();
    renderRanks(getRanks());
    updateScreen();
    showStatus("Данные успешно загружены из JSON");
  } catch (error) {
    console.error("[CONTROLLER] Ошибка загрузки:", error);
    showStatus("Ошибка: " + error.message, true);
  } finally {
    setLoading(false);
  }
}

Сначала view.js блокирует кнопку и меняет сообщение. Затем контроллер вызывает loadFighters().

export async function loadFighters() {
  const loaded = await fetchFighters();
  fighters = loaded;
  console.log("[MODEL] Сохранено бойцов:", fighters.length);
}
export async function fetchFighters() {
  const response = await fetch("./fighters.json", { cache: "no-store" });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}: не удалось получить fighters.json`);
  }
  const data = await response.json();
  if (!Array.isArray(data.squad)) {
    throw new Error("Неверный формат JSON: ожидается массив squad");
  }
  console.log("[DATA] JSON получен:", data);
  return data.squad;
}

fetch() запускает запрос и возвращает Promise — объект, представляющий будущий результат. await приостанавливает продолжение текущей async-функции, а не весь браузер. Сначала ожидается объект Response, затем response.json() разбирает тело ответа. После проверки формата data.js возвращает массив squad. Модель получает его как loaded и сохраняет ссылку в fighters. В исходном наборе 11 записей.

loadFighters() не возвращает массив: её Promise успешно завершается значением undefined. Контроллеру важно дождаться завершения изменения состояния модели. После этого он может запросить список званий и бойцов. Если запрос или проверка завершатся ошибкой, Promise будет отклонён; ошибка попадёт в catch контроллера.

8. Из массива в таблицу: первый рендеринг

renderRanks(getRanks());
updateScreen();

Вложенный вызов getRanks() выполняется раньше renderRanks(): сначала модель извлекает уникальные звания, затем представление получает массив строк и создаёт option в списке выбора. После этого контроллер вызывает updateScreen().

function updateScreen() {
  const filters = readFilters();
  const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);

  console.log("[CONTROLLER] Обновляем представление");
  renderFighters(visible);
  renderCounter(visible.length, getTotalCount());
}

При первом открытии поле поиска пустое, звание не выбрано, сортировка default. readFilters() возвращает объект {search: "", rank: "", sort: "default"}. Контроллер извлекает три свойства и передаёт их модели как три аргумента. Модель создаёт новый массив через filter(), при необходимости сортирует его и возвращает контроллеру. Для пустых фильтров в результате все 11 объектов в исходном порядке. Новый массив содержит ссылки на те же объекты бойцов, а не их глубокие копии.

export function renderFighters(fighters) {
  tbody.replaceChildren();
  fighters.forEach((fighter, index) => {
    const row = document.createElement("tr");
    const values = [index + 1, fighter.name, fighter.age,
      fighter.draftCity, fighter.rank, fighter.role];
    for (const value of values) {
      const cell = document.createElement("td");
      cell.textContent = value;
      row.append(cell);
    }
    tbody.append(row);
  });
  emptyMessage.hidden = fighters.length !== 0;
  console.log("[VIEW] Нарисовано строк таблицы:", fighters.length);
}

Представление очищает тело таблицы, перебирает массив, создаёт 11 строк по шесть ячеек и вставляет их в DOM. Это 66 ячеек. Браузер использует обновлённый DOM и CSS для отображения страницы. Файл index.html на диске при этом не изменяется. Затем getTotalCount() возвращает 11, а renderCounter(11, 11) меняет текст счётчика. Контроллер показывает сообщение об успехе и в finally разблокирует кнопку.

9. После запуска: события вместо линейного сценария

Первоначальная цепочка завершена, но приложение продолжает работать. Браузер ожидает события. При вводе «Москва» возникает input, зарегистрированный обработчик updateScreen вызывается браузером. Браузер передаёт объект события, однако исходная функция не объявляет параметр и не использует этот аргумент. Она сама читает актуальные поля через readFilters().

input→updateScreen()→readFilters()→getVisibleFighters()→renderFighters()

В модель поступают "Москва", "" и "default". Она нормализует текст, проверяет имя или город и выбранное звание, возвращает массив из одного объекта — Алексея Петрова. Представление заменяет 11 строк одной и обновляет счётчик до «Показано: 1 из 11». Повторного запроса к JSON нет.

При выборе звания или сортировки возникает change, вызывающий ту же функцию. При выборе «рядовой» после очистки поиска модель возвращает шесть бойцов; при ageAsc они располагаются от младшего к старшему. Модель сохраняет полный исходный массив. Фильтрация и сортировка результата не меняют его порядок.

Важно: обработчики вызываются при каждом соответствующем событии. В проекте нет задержки ввода (debounce). Даже во время загрузки кнопка заблокирована, но поля фильтров остаются доступными: они могут вызвать updateScreen с текущим состоянием модели.

10. Повторная загрузка и исключения

Кнопка reload при клике вызывает reloadData(). Теперь повторяется вся цепочка получения JSON, но не startController(): обработчики уже зарегистрированы. После успеха модель заменяет массив, представление обновляет список званий, сохраняя прежний выбор, если такое звание осталось. Текст поиска и сортировка не сбрасываются.

Если fetch завершится ошибкой или JSON окажется неправильной формы, выполнение перескочит в catch. При ошибке до присваивания fighters = loaded прежний массив сохраняется. Контроллер выводит сообщение об ошибке и в finally разблокирует кнопку. При первой неудачной загрузке массив остаётся пустым. В исходнике catch не вызывает очистку таблицы. Если исключение случилось уже после загрузки, например при рендеринге, новое состояние модели может быть сохранено.

Перезагрузка всей страницы — другое действие: браузер создаёт новый документ и заново запускает модули; переменные и обработчики старого документа не переиспользуются.

Импорт связывает имена между модулями. Аргументы передают значения при вызове. return возвращает значение вызывающей стороне. 14. Самопроверка
Почему HTML подключает только main.js?
Остальные модули браузер находит по графу import.
Когда создаётся пустой массив fighters?
При выполнении верхнего уровня model.js до main.js.
Почему view.js не импортирует DOM?
document предоставляется браузером.
Выполняется ли fetch при импорте data.js?
Нет, только при вызове fetchFighters().
Чем bindEvents(updateScreen, reloadData) отличается от bindEvents(updateScreen(), reloadData())?
Первое передаёт ссылки, второе вызывает функции и передаёт их возвращаемые значения.
Кто возвращает массив squad?
fetchFighters() через Promise, ожидаемый loadFighters().
Почему await loadFighters() не присваивается переменной?
Функция сохраняет массив внутри модели и не возвращает его.
Блокирует ли await браузер?
Нет, приостанавливает продолжение текущей async-функции.
Кто вызывает updateScreen при вводе текста?
Браузер через обработчик input, зарегистрированный view.js.
Почему фильтрация не загружает JSON?
updateScreen обращается к сохранённому массиву через модель.
Какой результат возвращает renderFighters?
undefined; полезный результат — изменение DOM.
Изменяется ли index.html на диске?
Нет, изменяется DOM в памяти.
Зачем finally?
Разблокировать кнопку после успеха или ошибки.
Чем повторная загрузка JSON отличается от F5?
Повторная загрузка заменяет данные в существующем приложении; F5 заново создаёт документ и запускает модули.
Итог
Браузер строит документ, загружает модули и запускает main.js. Тот вызывает контроллер, контроллер регистрирует события и запускает загрузку. Data возвращает массив модели, Model сохраняет и обрабатывает его, Controller передаёт результат View, View изменяет DOM. После первоначальной загрузки последовательность операций определяется событиями пользователя. Именно взаимодействие этих механизмов превращает набор отдельных файлов в работающую программу.
