1. Для чего нужна модель

В предыдущих уроках мы изучили загрузчик data.js и представление view.js. Первый получает массив из JSON, второе превращает готовый массив в HTML-таблицу. Между ними находится model.js — модуль, который хранит загруженные сведения и определяет правила их обработки. Контроллер вызывает функции модели и передаёт результаты представлению.

fighters.json → data.js → model.js → controller.js → view.js → DOM

DOM — объектное представление HTML-документа в памяти браузера. Модель не обращается к DOM: в ней нет document, querySelector или инструкций создания HTML. Она работает с обычными объектами, массивами, числами и строками. Когда пользователь меняет фильтр, контроллер передаёт модели три значения, а получает новый массив. JSON заново не загружается.

Что поступает в модель?

Из data.js — массив объектов; из controller.js — условия поиска, звание и способ сортировки, а также команды вызова функций. Из модели в контроллер возвращаются массив званий, число бойцов и массив отобранных объектов. При загрузке модель меняет своё внутреннее состояние и сообщает о завершении посредством Promise.

2. Импорт и внутреннее состояние

import { fetchFighters } from "./data.js"; // Импортируем данные из data.js

// MODEL: данные и правила их обработки. Никакого document или HTML.
let fighters = []; // Массив для хранения бойцов

Комментарий в исходнике говорит об импорте данных, но технически инструкция import импортирует функцию fetchFighters, а не массив. Данные поступят позднее, когда эта функция будет вызвана. Фигурные скобки в import обозначают именованный импорт: имя должно совпадать с именем экспортированного значения. ./data.js — путь к соседнему модулю.

let fighters = [] создаёт пустой массив и сохраняет ссылку на него в переменной fighters. let позволяет впоследствии присвоить переменной другой массив. Это состояние модуля — информация, сохраняющаяся между вызовами его функций. Переменная объявлена вне функций и не экспортируется, поэтому контроллер не может импортировать её напрямую. Все четыре функции модели работают с одной и той же привязкой fighters.

При первом вычислении модуля выполняется инициализация массива. Объявления функций не означают, что их тела уже выполнены. Загрузку запускает контроллер.

3. loadFighters() — загрузка и сохранение

export async function loadFighters() {
  // Загрузка бойцов
  const loaded = await fetchFighters(); // Получаем данные из data.js
  fighters = loaded; // Сохраняем бойцов в массив
  console.log("[MODEL] Сохранено бойцов:", fighters.length); // Логируем количество бойцов
}

export делает функцию доступной другим модулям. async объявляет асинхронную функцию: её вызов всегда возвращает Promise — объект, представляющий будущий результат или ошибку. await приостанавливает выполнение данной функции до завершения операции, не блокируя весь браузер.

Контроллер вызывает await loadFighters(). Внутри модели вызывается fetchFighters() из data.js. Загрузчик выполняет fetch, проверяет HTTP-ответ, преобразует JSON в объект JavaScript, проверяет наличие массива squad и возвращает data.squad. Поэтому loaded получает именно массив, а не весь объект JSON.

const loaded = await fetchFighters();
fighters = loaded;

Первая строка сохраняет ссылку на полученный массив в локальной переменной loaded. Вторая присваивает ту же ссылку переменной fighters. Копирования массива нет. Когда функция завершится, локальная переменная loaded перестанет быть доступной, но массив останется доступен через fighters.

console.log выводит диагностическое сообщение и длину массива (в исходном JSON 11 бойцов). Явного return нет. При успехе Promise выполняется со значением undefined, однако внутреннее состояние уже изменилось. При ошибке загрузки присваивание не происходит, Promise отклоняется, а контроллер перехватывает ошибку своим catch. При повторной неудачной загрузке прежний массив остаётся в модели.

controller: await loadFighters() → data: fetchFighters() → loaded → fighters

4. getRanks() — список уникальных званий

export function getRanks() {
  // Получение списка рангов бойцов
  return [...new Set(fighters.map((fighter) => fighter.rank))].sort((a, b) =>
    a.localeCompare(b, "ru")
  ); // Сортировка уникальных рангов
}

Функция не принимает аргументов. Она читает сохранённый массив fighters и возвращает новый массив строк. Разберём вложенные операции изнутри наружу.

Шаг 1. map() — извлечение свойства

fighters.map((fighter) => fighter.rank)

Метод map вызывает переданную функцию для каждого объекта и создаёт новый массив из возвращённых значений. fighter — параметр стрелочной функции, очередной объект бойца. Справа от стрелки записано выражение fighter.rank. Поскольку фигурных скобок вокруг тела нет, значение возвращается автоматически. В новом массиве столько же элементов, сколько в исходном: 11, в том числе повторяющиеся звания.

Шаг 2. Set — удаление повторов

new Set(fighters.map((fighter) => fighter.rank))

Set — коллекция уникальных значений. Конструктор new Set принимает массив и оставляет каждую строку только один раз. Порядок первого появления сохраняется. В нашем случае остаются четыре звания: сержант, младший сержант, рядовой, ефрейтор.

Шаг 3. Spread — разворачивание коллекции

[...new Set(fighters.map((fighter) => fighter.rank))]

Три точки (...) здесь — синтаксис разворачивания (spread). Он перечисляет элементы Set внутри квадратных скобок и создаёт обычный массив. Это необходимо, потому что у Set нет метода sort.

Шаг 4. sort() — сортировка строк

.sort((a, b) => a.localeCompare(b, "ru"))

sort переставляет элементы массива. Функция сравнения получает два элемента a и b; отрицательный результат ставит a перед b, положительный — после b, ноль означает равенство для целей сортировки. localeCompare сравнивает строки с учётом правил указанного языка. Код ru задаёт русскую локаль. Результат: ефрейтор, младший сержант, рядовой, сержант.

return передаёт массив контроллеру. Вызов renderRanks(getRanks()) сначала получает массив, а затем передаёт его представлению. Исходный fighters не меняется.

5. getTotalCount() — количество бойцов
export function getTotalCount() {
  // Получение общего количества бойцов
  return fighters.length; // Возвращаем количество бойцов
}
Функция не получает аргументов, а читает состояние модуля. length — свойство массива, содержащее его длину. После успешной загрузки исходных данных оно равно 11; до загрузки — 0. Фильтрация этого числа не меняет, поскольку исходный массив сохраняется. Контроллер передаёт его функции renderCounter вместе с длиной отфильтрованного массива. Если выбрано звание «рядовой», на странице появится «Показано: 6 из 11».
6. getVisibleFighters() — поиск, фильтрация и сортировка
Это основная функция обработки данных. Она получает от контроллера три строки и возвращает массив объектов, удовлетворяющих условиям пользователя. Рассмотрим исходный код по блокам.
export function getVisibleFighters(
  searchText = "",
  rank = "",
  sort = "default"
) {
  // Получение отфильтрованных бойцов
  const query = searchText.trim().toLocaleLowerCase("ru"); // Обработка поискового запроса
ПараметрИсточникПримерЗначение по умолчанию
searchTextПоле поиска через readFilters() и контроллер" Москва """
rankСписок званий через контроллер"рядовой"""

Значения по умолчанию используются, если аргумент отсутствует или равен undefined. Пустой поиск и пустое звание означают отсутствие соответствующих ограничений; default сохраняет исходный порядок. trim() удаляет пробельные символы с начала и конца строки. toLocaleLowerCase("ru") переводит буквы в нижний регистр. Например, « МОСКВА » превращается в «москва». Исходная строка не меняется: создаётся новая.
6.1. filter() — создание нового массива
  const result = fighters.filter((fighter) => {
    // Фильтрация бойцов
    const matchesText = [fighter.name, fighter.draftCity] // Проверка на вхождение в имя или город
      .some((value) => value.toLocaleLowerCase("ru").includes(query)); //
    const matchesRank = !rank || fighter.rank === rank; // Проверка на соответствие рангу
    return matchesText && matchesRank; // Фильтрация
  });
filter перебирает массив и вызывает функцию-проверку для каждого бойца. Если она возвращает true, объект включается в новый массив; если false — пропускается. В отличие от map, filter может уменьшить количество элементов, но не преобразует сами объекты. result — новый массив, содержащий ссылки на исходные объекты.
6.2. Проверка текста: some() и includes()
const matchesText = [fighter.name, fighter.draftCity]
  .some((value) => value.toLocaleLowerCase("ru").includes(query));
Сначала создаётся массив из двух строк: имени и города очередного бойца. Метод some проверяет, удовлетворяет ли хотя бы один элемент условию. Внутренняя стрелочная функция получает строку value, переводит её в нижний регистр и методом includes проверяет, содержится ли в ней поисковый запрос. some прекращает перебор при первом успешном совпадении. Пустая строка содержится в любой строке, поэтому при пустом поиске matchesText всегда true для корректных строк.
Например, у Алексея Петрова имя не содержит «москва», но город содержит. Следовательно, matchesText равно true. Должность и звание в текстовом поиске не участвуют. Поиск проверяет подстроку, а не точное совпадение или сходство слов.
6.3. Проверка звания и объединение условий
const matchesRank = !rank || fighter.rank === rank;
return matchesText && matchesRank;
! — логическое отрицание. Для пустой строки !rank равно true. || — логическое ИЛИ: если первое условие истинно, второе не вычисляется. Если звание задано, проверяется строгое равенство ===. Оно требует совпадения значения и типа; здесь сравниваются строки. && — логическое И: для включения бойца в результат должны быть истинны обе проверки.

Внутренний return возвращает логическое значение методу filter, а не контроллеру. Только внешний return result в конце функции возвращает весь обработанный массив. Это два разных уровня вызова.
6.4. Сортировка результата
  if (sort === "name")
    result.sort((a, b) => a.name.localeCompare(b.name, "ru")); // Сортировка по имени
  if (sort === "ageAsc") result.sort((a, b) => a.age - b.age); // Сортировка по возрасту
  if (sort === "ageDesc") result.sort((a, b) => b.age - a.age); // Сортировка по возрасту в обратном порядке

  console.log("[MODEL] После обработки:", result.length); // Логируем количество бойцов после обработки
  return result; // Возвращаем отфильтрованные бойцов
}
Три инструкции if проверяют способ сортировки. При name сравниваются полные имена по русским правилам. При ageAsc вычитается возраст второго бойца из возраста первого: если a.age = 20, b.age = 28, результат −8, поэтому a располагается раньше b. При ageDesc вычитание обращено, и старший оказывается раньше. При default ни одно условие не выполняется. Равные по возрасту сохраняют относительный порядок исходного массива (стабильная сортировка современного JavaScript).
sort изменяет сам массив, на котором вызван. Здесь это result, созданный filter, а не fighters. Поэтому последующий вызов с default снова покажет исходный порядок. Копирование неглубокое: если бы мы изменяли свойства объектов внутри result, это затронуло бы и исходные объекты. Данная функция этого не делает.
console.log сообщает количество оставшихся бойцов. return result передаёт новый массив контроллеру, который сохраняет его в visible и вызывает renderFighters(visible). В модели HTML не создаётся.

8. Полная последовательность работы
Первоначальная загрузка и повторная загрузка
main.js импортирует startController и вызывает его. Контроллер назначает обработчики событий через bindEvents, затем вызывает reloadData. Представление блокирует кнопку и сообщает о загрузке. Контроллер ожидает loadFighters; модель получает массив от data.js и сохраняет его. Затем контроллер вызывает getRanks и передаёт список в renderRanks. После этого updateScreen читает фильтры через readFilters, передаёт их getVisibleFighters, передаёт массив renderFighters и два числа renderCounter. При успехе выводится сообщение о загрузке, при ошибке — сообщение об ошибке. finally разблокирует кнопку в обоих случаях.
// controller.js — реальные вызовы модели
await loadFighters();
renderRanks(getRanks());
updateScreen();

// Внутри updateScreen():
const filters = readFilters();
const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);
renderFighters(visible);
renderCounter(visible.length, getTotalCount());
Изменение фильтра
Браузер вызывает updateScreen при вводе текста или изменении списка. Контроллер считывает значения, модель обрабатывает сохранённый массив, представление перерисовывает таблицу. loadFighters и getRanks при обычной фильтрации не вызываются. Это уменьшает число запросов к источнику.
DOM: input/change → controller: updateScreen() → view: readFilters() → model: getVisibleFighters() → view: renderFighters()

10. Самопроверка
Что импортирует model.js?
Функцию fetchFighters, а не данные.
Когда fighters перестаёт быть пустым?
После успешного await fetchFighters и присваивания fighters = loaded.
Почему loadFighters не содержит return?
Её цель — изменить состояние. Асинхронная функция возвращает Promise, который при успехе выполняется со значением undefined.
Что возвращает map, а что filter?
map создаёт массив результатов преобразования каждого элемента; filter создаёт массив прошедших проверку элементов.
Зачем нужны Set и spread?
Set удаляет повторы, spread превращает коллекцию в обычный массив.
Кому адресован return matchesText && matchesRank?
Методу filter, который вызвал функцию-проверку.
Почему сортировка не меняет исходный порядок?
sort вызывается на новом массиве result, созданном filter.
Что произойдёт при поиске МОСКВА и звании рядовой?
Ни одного результата: Алексей Петров из Москвы имеет звание сержант.
Нужно ли повторно читать JSON при смене звания?
Нет, модель использует сохранённые данные.
