1. Зачем нужен контроллер

В предыдущих уроках мы изучили модель, которая хранит и обрабатывает массив бойцов, и представление, которое читает поля интерфейса и строит таблицу. Но кто решает, когда вызвать эти функции и в каком порядке? Этим занимается controller.js.

Контроллер — управляющий модуль. Он связывает пользовательские действия с операциями модели и обновлением представления. Он не загружает JSON самостоятельно, не фильтрует массив собственным циклом и не создаёт HTML-элементы. Вместо этого он вызывает функции других модулей.

Пользователь / браузер→view.js: событие→controller.js→model.js: обработка→view.js: отображение
МодульОтветственностьЧто не делает
data.jsЧитает fighters.json и возвращает squadНе строит таблицу
model.jsХранит массив, отбирает, сортируетНе обращается к DOM
view.jsЧитает поля, меняет DOM, регистрирует событияНе фильтрует исходный массив
controller.jsОпределяет последовательность вызововНе реализует обработку данных и построение DOM
main.jsВызывает startController()Не управляет отдельными операциями

В контроллере нет собственного массива бойцов, сохраняемого между вызовами. Его локальная переменная visible существует внутри updateScreen(). Долговременное состояние массива принадлежит модели.

2. Исходный код

Ниже приведён код из проекта MVC Fighters, без изменений. Далее разберём его в порядке исполнения, а не только расположения строк в файле.

import { loadFighters, getRanks, getTotalCount, getVisibleFighters } from "./model.js";
import { bindEvents, readFilters, renderRanks, renderFighters, renderCounter, showStatus, setLoading } from "./view.js";

// CONTROLLER: связывает действия пользователя, модель и представление.
function updateScreen() {
  const filters = readFilters();
  const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);

  console.log("[CONTROLLER] Обновляем представление");
  renderFighters(visible);
  renderCounter(visible.length, getTotalCount());
}

async function reloadData() {
  setLoading(true);
  showStatus("Читаем fighters.json…");
  try {
    await loadFighters();
    renderRanks(getRanks());
    updateScreen();
    showStatus("Данные успешно загружены из JSON");
  } catch (error) {
    console.error("[CONTROLLER] Ошибка загрузки:", error);
    showStatus("Ошибка: " + error.message, true);
  } finally {
    setLoading(false);
  }
}

export function startController() {
  bindEvents(updateScreen, reloadData);
  reloadData();
}

3. Импорт: что именно получает controller.js

Контроллер импортирует одиннадцать функций: четыре из модели и семь из представления. Импорт не вызывает функцию и не загружает массив бойцов. Он делает экспортированные функции доступными под их именами. Данные контроллер получит позже, при вызове функций.

import { loadFighters, getRanks, getTotalCount, getVisibleFighters } from "./model.js";
import { bindEvents, readFilters, renderRanks, renderFighters, renderCounter, showStatus, setLoading } from "./view.js";
ОткудаФункцияЧто контроллер получает при вызове / что поручает
model.jsloadFighters()Promise; поручает загрузить и сохранить данные
model.jsgetRanks()Массив уникальных званий
model.jsgetTotalCount()Число всех бойцов
model.jsgetVisibleFighters(search, rank, sort)Новый массив отобранных и отсортированных бойцов
view.jsbindEvents(onFilterChange, onReload)Поручает зарегистрировать обработчики
view.jsreadFilters()Объект с тремя значениями полей
view.jsrenderRanks(ranks)Поручает заполнить список званий
view.jsrenderFighters(fighters)Поручает построить таблицу
view.jsrenderCounter(visible, total)Поручает изменить счётчик

Фигурные скобки в import { ... } обозначают именованный импорт. Они не создают объект с данными. Относительный путь ./model.js означает файл в той же папке.

Сам контроллер экспортирует только startController. Две остальные функции доступны внутри модуля. Однако ссылки на них можно передать наружу в качестве аргументов, что и происходит при подписке на события.

4. startController(): запуск приложения

HTML подключает main.js как модуль. В нём находятся следующие инструкции:

import { startController } from "./controller.js";
console.log("[MAIN] Запуск приложения MVC");
startController();
export function startController() {
  bindEvents(updateScreen, reloadData);
  reloadData();
}

Функция не имеет параметров: для запуска не нужны ни массив бойцов, ни значения фильтров. Первая инструкция передаёт две функции в представление. Вторая начинает первоначальную загрузку данных.

Передача функции и её вызов

bindEvents(updateScreen, reloadData);

Здесь имена написаны без круглых скобок. Передаются сами функции (точнее, ссылки на функциональные объекты). Если написать updateScreen(), функция будет вызвана немедленно, а вместо неё в bindEvents попадёт её возвращаемое значение — undefined.

export function bindEvents(onFilterChange, onReload) {
  searchInput.addEventListener("input", onFilterChange);
  rankSelect.addEventListener("change", onFilterChange);
  sortSelect.addEventListener("change", onFilterChange);
  reloadButton.addEventListener("click", onReload);
}

Обработчик события — функция, которую браузер вызывает при наступлении определённого события. Слово callback (функция обратного вызова) обозначает функцию, переданную другой части программы для последующего вызова.

СобытиеЭлементЧто вызовет браузер
inputПоле поискаupdateScreen
changeСписок званийupdateScreen
changeСписок сортировкиupdateScreen
clickКнопка загрузкиreloadData

После регистрации обработчиков reloadData() вызывается сразу. Это не событие: обычный вызов функции из startController. Сам startController возвращает undefined и не ожидает завершения асинхронной загрузки.

5. reloadData(): загрузка, ожидание и обработка ошибок

async function reloadData() {
  setLoading(true);
  showStatus("Читаем fighters.json…");
  try {
    await loadFighters();
    renderRanks(getRanks());
    updateScreen();
    showStatus("Данные успешно загружены из JSON");
  } catch (error) {
    console.error("[CONTROLLER] Ошибка загрузки:", error);
    showStatus("Ошибка: " + error.message, true);
  } finally {
    setLoading(false);
  }
}

Шаг 1. Изменение интерфейса перед загрузкой

setLoading(true);
showStatus("Читаем fighters.json…");

Контроллер передаёт в view.js значение true. Представление блокирует кнопку повторной загрузки и меняет её текст. Затем контроллер передаёт строку состояния. Здесь не загружаются данные: пользователь лишь получает сообщение о начале операции.

Шаг 2. Ожидание модели

await loadFighters();

async объявляет асинхронную функцию. При вызове такая функция возвращает Promise — объект, представляющий будущий результат или ошибку операции. await приостанавливает продолжение данной асинхронной функции до завершения Promise, но не блокирует весь браузер.

loadFighters() вызывает fetchFighters() из data.js, ждёт массив и записывает его во внутреннюю переменную fighters. Функция не возвращает сам массив. При успешном завершении её Promise выполняется со значением undefined. Контроллеру здесь нужен факт завершения загрузки, а не массив как результат.

controller: await loadFighters()→model: await fetchFighters()→data: fetch + json()→model: fighters = loaded→controller: продолжение

Шаг 3. Заполнение списка званий

renderRanks(getRanks());

Вложенный вызов выполняется изнутри наружу: сначала getRanks() возвращает массив уникальных званий, затем этот массив становится аргументом renderRanks(). Можно записать те же действия более развёрнуто:

const ranks = getRanks();
renderRanks(ranks);

Представление перестраивает список званий и сохраняет прежний выбор, если такое звание всё ещё существует в новых данных.

Шаг 4. Обновление экрана

updateScreen();
showStatus("Данные успешно загружены из JSON");

Контроллер запускает обычную синхронную функцию обновления таблицы, а затем выводит сообщение об успехе. При повторной загрузке учитываются текущие фильтры, а не обязательно все бойцы.

Шаг 5. Ошибка

catch (error) {
  console.error("[CONTROLLER] Ошибка загрузки:", error);
  showStatus("Ошибка: " + error.message, true);
}

try содержит операции, при которых может возникнуть исключение. Если загрузка завершается ошибкой или какая-либо последующая инструкция в try выбрасывает исключение, управление переходит в catch. Параметр error содержит объект ошибки; error.message — её текст. Второй аргумент true указывает представлению применить оформление ошибки.

Если ошибка произошла до присваивания нового массива модели, ранее загруженные данные остаются в памяти. При ошибке первоначальной загрузки массив остаётся пустым. В коде нет явного очищения таблицы при ошибке. Если ошибка произошла позднее, часть интерфейса уже могла измениться.

Шаг 6. Завершение операции

finally {
  setLoading(false);
}

Блок finally выполняется после try или catch. Кнопка снова доступна независимо от успеха загрузки. В исходном коде первые два вызова setLoading и showStatus стоят до try, поэтому исключения в них этим catch не перехватываются.

reloadData() возвращает Promise, который при обычном успешном завершении или обработанной ошибке выполняется со значением undefined. Результаты её работы — изменение состояния модели и интерфейса.

6. updateScreen(): обновление таблицы

function updateScreen() {
  const filters = readFilters();
  const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);

  console.log("[CONTROLLER] Обновляем представление");
  renderFighters(visible);
  renderCounter(visible.length, getTotalCount());
}

Шаг 1. Получение условий отбора

const filters = readFilters();

readFilters() обращается к DOM и возвращает объект. Например, пользователь ввёл «Москва» и выбрал сортировку по возрастанию возраста:

{ search: "Москва", rank: "", sort: "ageAsc" }

Пустая строка rank означает «Все звания». Объект сохраняется в локальной переменной filters. Контроллер не читает DOM напрямую.

Шаг 2. Передача условий модели

const visible = getVisibleFighters(filters.search, filters.rank, filters.sort);

Контроллер извлекает три свойства объекта и передаёт их как три позиционных аргумента. Модель принимает их в параметрах searchText, rank и sort. Параметры — имена в объявлении функции; аргументы — конкретные значения в момент вызова.

Аргумент контроллераПараметр моделиПример
filters.searchsearchText"Москва"
filters.rankrank""
filters.sortsort"ageAsc"

Модель нормализует поисковый текст, отбирает бойцов по имени или городу и званию, сортирует новый массив, возвращает его через return. Контроллер сохраняет ссылку на него в visible. При фильтрации нового запроса к JSON нет.

Шаг 3. Сообщение в консоль

console.log("[CONTROLLER] Обновляем представление");

Сообщение предназначено разработчику. Оно помогает проследить очередность вызовов, но не выводит текст на веб-страницу.

Шаг 4. Передача массива представлению

renderFighters(visible);

Представление получает массив через параметр fighters, очищает тело таблицы, создаёт строки и ячейки, меняет видимость сообщения об отсутствии результатов. Контроллер не создаёт HTML самостоятельно.

Шаг 5. Счётчик

renderCounter(visible.length, getTotalCount());

Первый аргумент — длина отфильтрованного массива, второй — общее количество бойцов модели. Вызов getTotalCount() выполняется прежде, чем начнётся renderCounter(). Например, при поиске Москвы в исходном массиве из 11 записей получится «Показано: 1 из 11».

Функция updateScreen() ничего явно не возвращает. Её результат — обновлённая страница. Она может вызываться как из reloadData(), так и браузером при событии. Браузер передаёт объект события, но функция его не использует: актуальные условия она читает через readFilters().

Два вида результата

Возвращаемое значение — то, что получает вызывающий код через return (или Promise). Побочный эффект — изменение состояния вне локального вычисления: например, обновление DOM, регистрация события или сохранение массива в модели. Все три функции контроллера нужны прежде всего ради таких действий. Они не являются функциями преобразования, возвращающими готовый массив или HTML.

Поиск, выбор звания и сортировка

input / change→updateScreen→readFilters→getVisibleFighters→renderFighters + renderCounter

Модель использует уже сохранённый массив. Не вызываются loadFighters, renderRanks, setLoading и showStatus. При изменении поля поиска событие input возникает при каждом изменении значения пользователем.

Повторная загрузка

click→reloadData→loadFighters→renderRanks→updateScreen→finally

При успехе исходный массив заменяется, список званий перестраивается, а таблица обновляется с учётом текущего выбора. При ошибке внутри try управление переходит к catch, затем finally. Повторная подписка на события не нужна.

Что случится, если перепутать порядок?

Если убрать await, контроллер может прочитать старый или пустой массив до завершения запроса. Если вызвать renderFighters до getVisibleFighters, ему нечего будет передать. Если убрать finally и не восстановить кнопку при ошибке, повторная загрузка может стать недоступна.

9. Интерактивная лаборатория контроллера

Лаборатория воспроизводит взаимодействие четырёх модулей. Используется исходный набор из 11 бойцов; fetchFighters имитирует асинхронный запрос с задержкой 450 мс и умеет имитировать ошибку. Это автономная демонстрация, не настоящий сетевой запрос. Все остальные основные операции соответствуют исходному коду; журнал дополнен учебными сообщениями о передаче данных.

10. Самопроверка
Почему контроллер импортирует функции, а не массив бойцов?
Массив принадлежит модели; контроллер получает необходимые данные через вызовы её публичных функций.
Кто вызывает startController()?
main.js.
Почему bindEvents(updateScreen, reloadData) записано без скобок у аргументов?
Передаются ссылки на функции для последующего вызова, а не результаты немедленного исполнения.
Что возвращает readFilters()?
Объект с search, rank и sort.
Что получает await loadFighters()?
При успехе undefined; await нужен для ожидания завершения сохранения массива.
Кто вызывает updateScreen при поиске?
Браузер через зарегистрированный обработчик input.
Почему фильтрация не вызывает fetch?
updateScreen обращается к сохранённому массиву модели.
Чем отличается visible.length от getTotalCount()?
Первое число — количество отобранных бойцов, второе — количество всех бойцов в модели.
Что происходит при ошибке загрузки?
Выполняется catch, выводится сообщение, finally восстанавливает кнопку.
Что возвращает reloadData()?
Promise; при обычном завершении он выполняется со значением undefined.
Почему в контроллере нет document.querySelector?
Доступ к DOM делегирован представлению.
Кто принимает решение, когда обновить таблицу?
Контроллер; представление выполняет порученное обновление.
Итог: контроллер принимает решение о порядке вызовов, получает значения из представления, передаёт их модели и возвращает обработанные данные представлению для отображения.
